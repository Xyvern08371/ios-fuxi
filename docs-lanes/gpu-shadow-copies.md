# Wrapped-buffer shadow copies

`FuxiBuffer::_shadow` is set only by `newBufferWithBytesNoCopy:length:options:deallocator:` when `Backend::importBuffer` fails. The supported option is shared storage. Import requires host-import support, a non-null pointer, host-aligned address and length, a compatible memory type, and successful Vulkan allocation/import/mapping. QuartzCore also wraps unaligned or read-only copy-on-write CGImage pages that cannot be wired for GPU access. Fuxi then allocates an ordinary mapped Vulkan buffer, copies the initial contents, and keeps the caller's pointer as `contents`. GPU writes to that allocation do not propagate back to the caller's pages.

The logical size is exactly the caller's `length`, stored in `_wrappedLength` and the backend buffer's `length`; this is not the currently active ring window. Allocation requests are bounded by `ResourceLimits::single` (128 MiB) and the 256 MiB resource budget. Vulkan allocation size can include padding. Neither the supplied trace medians nor the code establish a measured distribution of CA buffer lengths. The 4 MiB buffer below is an authored test workload, not a measured device allocation size.

Before this change, overlap-mode `commit` scanned retained resources, found shadow buffers directly and through buffer textures, and allocated a byte vector containing every byte of each distinct wrapped allocation. The submit worker later copied each whole snapshot into the mapped GPU allocation. The synchronous path copied whole wrapped allocations directly during commit. The initial construction copy remains unchanged.

## Commit guarantee and bounds

For shadowed wrapped buffers, every byte that the committed command can observe must reflect the value captured before `commit` returns. CPU writes after that return must not change the committed frame. Snapshotting at worker execution would break this guarantee. Applications still must serialize encoding and must not race CPU writes with the snapshot itself. This work concerns the existing shadow fallback; successfully imported shared buffers retain their existing synchronization behavior.

Each command buffer now tracks a union of half-open byte intervals for each shadow allocation while encoding. Buffer setters register ownership; draws consume the bindings and offsets effective at that draw, including bulk setters and offset-only changes. Rebinding does not remove intervals needed by an earlier draw. Stage and slot are independent, while intervals referring to the same allocation merge across stages, slots, draws and render encoders. Adjacent intervals also merge. Binding a resource without drawing creates no read requirement.

The optional ABI-8 adapter extension `fuxi_m2v_shadow_windows_v1` exports immutable shader access proofs once at pipeline creation. These come from the translator's public compiled pipeline interface, not from guesses based on binding offsets, descriptor minimum sizes or neighboring ring entries. Each stage/slot is either unknown/whole, a proven signed-offset byte window, or statically unused. Read-only descriptor buffers with a proven `Window::Bounded` can use the smaller window. Signed starts, addition overflow and allocation bounds are checked before an interval is accepted.

Vertex descriptor fetches (fixed-function or translator-pulled) additionally contribute the range from the first fetched attribute byte through the last vertex's attribute end, using the validated per-vertex stride, attribute offset/format width, vertex start and vertex count. All declared attributes are considered conservatively, including gaps between vertices. Pulled vertex inputs synthesize whole-buffer slots in the combined interface. For those candidates, the adapter reflects the specialized vertex descriptor with its vertex-layout prefix removed, once at pipeline creation: only the proven absence of any shader argument at that index permits replacing the synthetic whole slot with the attribute ranges. Reflection failure or a real argument at that index retains the whole-buffer fallback. A slot used by both a vertex fetch and a shader argument takes their union. Indexed vertex fetches use the entire bound shadow allocation: indices may change before commit or be GPU-side, so encoding-time CPU index inspection cannot establish a stable vertex bound. Index buffers themselves also retain the full-copy fallback. `setVertexBytes` and `setFragmentBytes` already own separate allocations copied at encoding and never become wrapped shadows.

Every unknown proof, whole/dynamic window, device-address form, writable buffer, function-table form, malformed/out-of-bounds window, or unavailable/older adapter keeps the whole allocation. Pipelines needing pointer/handle translation or reaching indirect command buffers provide no smaller proof. `useResource`, blits and buffer-backed textures also mark the underlying shadow allocation whole, even if a previous draw had a bounded use. This fallback is sticky for the command buffer. Unsupported indirect/argument-buffer selectors continue to reject submission; their support is not expanded here. Newly supported accesses must either supply a proven range or use the default whole-resource retention path.

## Packed storage and submission

Commit packs the merged intervals into one command-owned snapshot, preserving each destination offset separately. A queue-local, mutex-protected pool holds two reusable byte allocations, matching the usual two-flight queue. It retains capacity across frames and allocates uninitialized storage only when no idle allocation is large enough; it does not zero a whole vector before overwriting it. Small interval/segment metadata can still allocate. Each pending commit owns its allocation exclusively. Another commit cannot reuse it until application of the snapshot has finished.

The existing backend prepare callback still drains prior uses before refreshing the shared mapped GPU buffer. Refresh copies only the recorded intervals to their original offsets, then immediately returns the CPU snapshot allocation to the pool. GPU commands reference the mapped buffer, never the pooled snapshot. Failure/retirement and command destruction also return any outstanding storage. Resource owners remain retained through retirement. The synchronous commit path applies the same intervals directly before returning and needs no intermediate snapshot.

Bytes outside the union may retain old GPU-allocation contents. The access proof guarantees that they cannot influence this command's result. Writing those CPU bytes after commit therefore cannot change its output; writing inside the union also cannot change it because those bytes have already been captured. A later command using a different ring window captures that window's then-current contents.

Existing timing/trace fields, including `snapshot`, `shadow_copy`, and `commit_call`, remain. Frame traces add `snapshot_bytes/frame` and `shadow_copy_bytes/frame`, averaged over the same reporting window and reset with it. Counts describe actual snapshot and GPU-allocation refresh bytes, including full fallbacks and deduplicating aliases. Synchronous commits report zero intermediate snapshot bytes and the direct refresh bytes. Initial buffer construction and unrelated texture upload copies are excluded.

## Host evidence

`ShadowRangesTests.cpp`, registered in `tools/test-fuxi-metal-frontend.py`, runs on Linux/macOS with ASan/UBSan. It checks interval merging against an independent byte-mask oracle, negative/overflowing/out-of-bounds proofs, fixed-function fetch bounds, indexed/unknown fallback, pool reuse across threads, independent pending snapshots, and post-commit mutations inside/outside the union. `FrameTraceTests.cpp` checks the byte fields and reporting reset. `ShadowFrontendTests.mm` exercises real Objective-C selectors against `TestBackend.hpp` with the submit queue paused: bulk bindings, offset updates, multiple draws, inline bytes, full fallbacks after a bounded use, byte accounting, and mutations after commit. It is registered for native execution and compile-only checks on macOS; it cannot compile or run on Linux without Foundation/Metal.

`tools/test-fuxi-metal-shadows.py` runs the host controls and optionally accepts an existing local ICD and glslang executable for production-backend pixel tests. It authors its own GLSL uniform-buffer fixture. Full and ranged snapshots produce byte-identical lavapipe pixels after CPU memory is overwritten following capture, with independently expected BGRA bytes. Controls cover synchronous/overlap submission and an old adapter without the optional proof extension. `--translator` additionally checks the real adapter against the hand-authored AIR control, verifying bounded vertex/fragment uniforms and the vertex descriptor union, including a full fallback when a shader argument shares that slot. The optional Vulkan test is registered alongside the existing render-merge test in `tools/ci/build.sh`; no barrier, merge or DrawPlanCache policy is changed.

The CA-like host ring contains 130 draws per frame. Each uses six vertices at stride 32 (two float4 attributes), followed by 64 fragment bytes: 256 bytes per draw. The active windows are contiguous within a 4 MiB ring and rotate between frames.

| Per-frame CPU copy | Before | After |
| --- | ---: | ---: |
| Commit snapshot | 4,194,304 bytes | 33,280 bytes |
| Backend shadow refresh | 4,194,304 bytes | 33,280 bytes |
| Both stages | 8,388,608 bytes | 66,560 bytes |

This is a 99.21% byte reduction for the authored pattern. An unbounded access still copies all 4,194,304 bytes per stage. Device timing improvement is unmeasured: no device access or macOS build was performed. The supplied device baseline remains `commit_call=3.22 ms`, snapshot about 2.7 ms, `shadow_copy=1.39 ms` median / 1.83 ms p90, and frame-wall p50 15.9 ms.

Linux validation for this change: the frontend host suite and frame-trace regression passed; the shadow host/pixel suite passed with the new and old fixture adapters in both submission modes; the real-adapter authored AIR reflection control passed. The production adapter was compile-checked and built offline with Rust 1.98.0 against the already available external source, and its unit suite passed (11 passed, one pre-existing benchmark ignored). Shell syntax, Python compilation, CI dry-run and diff whitespace checks passed. No native Objective-C test was compiled or executed.
