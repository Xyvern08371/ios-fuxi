# Wrapped-buffer shadow copies

`FuxiBuffer::_shadow` is set only by `newBufferWithBytesNoCopy:length:options:deallocator:` when `Backend::importBuffer` fails. The supported option is shared storage. Import requires host-import support, a non-null pointer, host-aligned address and length, a compatible memory type, and successful Vulkan allocation/import/mapping. QuartzCore also wraps unaligned or read-only copy-on-write CGImage pages that cannot be wired for GPU access. Fuxi then allocates an ordinary mapped Vulkan buffer, copies the initial contents, and keeps the caller's pointer as `contents`. GPU writes to that allocation do not propagate back to the caller's pages.

The logical size is exactly the caller's `length`, stored in `_wrappedLength` and the backend buffer's `length`; this is not the currently active ring window. Allocation requests are bounded by `ResourceLimits::single` (128 MiB) and the 256 MiB resource budget. Vulkan allocation size can include padding. Neither the supplied trace medians nor the code establish a measured distribution of CA buffer lengths. The 4 MiB buffer below is an authored test workload, not a measured device allocation size.

Before this change, overlap-mode `commit` scanned retained resources, found shadow buffers directly and through buffer textures, and allocated a byte vector containing every byte of each distinct wrapped allocation. The submit worker later copied each whole snapshot into the mapped GPU allocation. The synchronous path copied whole wrapped allocations directly during commit. The initial construction copy remains unchanged.

## Commit guarantee and bounds

For shadowed wrapped buffers, every byte that the committed command can observe must reflect the value captured before `commit` returns. CPU writes after that return must not change the committed frame. Snapshotting at worker execution would break this guarantee. Applications still must serialize encoding and must not race CPU writes with the snapshot itself. This work concerns the existing shadow fallback; successfully imported shared buffers retain their existing synchronization behavior.

Each command buffer now tracks a union of half-open byte intervals for each shadow allocation while encoding. Buffer setters register ownership; draws consume the bindings and offsets effective at that draw, including bulk setters and offset-only changes. Rebinding does not remove intervals needed by an earlier draw. Stage and slot are independent, while intervals referring to the same allocation merge across stages, slots, draws and render encoders. Adjacent intervals also merge. Binding a resource without drawing creates no read requirement.

The optional ABI-8 adapter extension `fuxi_m2v_shadow_windows_v1` exports immutable shader access proofs once at pipeline creation. These come from the translator's public compiled pipeline interface, not from guesses based on binding offsets, descriptor minimum sizes or neighboring ring entries. Each stage/slot is either unknown/whole, a proven signed-offset byte window, or statically unused. Read-only descriptor buffers with a proven `Window::Bounded` can use the smaller window. Signed starts, addition overflow and allocation bounds are checked before an interval is accepted.

Vertex descriptor fetches (fixed-function or translator-pulled) additionally contribute the range from the first fetched attribute byte through the last vertex's attribute end, using the validated per-vertex stride, attribute offset/format width, vertex start and vertex count. All declared attributes are considered conservatively, including gaps between vertices. Pulled vertex inputs synthesize whole-buffer slots in the combined interface. For those candidates, the adapter reflects the specialized vertex descriptor with its vertex-layout prefix removed, once at pipeline creation: only the proven absence of any shader argument at that index permits replacing the synthetic whole slot with the attribute ranges. Reflection failure or a real argument at that index retains the whole-buffer fallback. A slot used by both a vertex fetch and a shader argument takes their union. Indexed draws defer this calculation until commit. The index byte interval itself is included in the shadow union. For shadowed indices, commit first captures the union of eligible index intervals into command-owned packed storage, then scans those frozen bytes for the minimum and maximum referenced vertex. It applies attribute bounds to that inclusive range. Both u16 and u32 indices are supported; `0xFFFF`/`0xFFFFFFFF` are skipped only for triangle/line strips, matching `primitiveRestart` in the backend. List topologies treat those values as ordinary indices. All-restart strips add no vertex fetch interval. Invalid vertex bounds preserve the full allocation. The frontend still has no base-vertex selector; the checked range helper covers signed base arithmetic, while admitted draws use base zero.

The cache has 64 entries and lives only for this commit's immutable index snapshot. Its key includes buffer identity, offset, count, width and restart mode; no result survives into a later contents version. At most 65,536 indices per draw and 262,144 indices per command are captured for scans, conservatively charging repeated draws against the capture budget; cache hits do not rescan. Over-budget or unavailable frozen bytes retain the indexed full fallback. Ordinary mapped/imported index buffers have no committed-frame immutability guarantee, so they retain full vertex copies without scanning. Shadow indices marked whole by explicit resource/texture/blit uses, or written by this command, also retain that fallback. Existing GPU-written-index submission refusals remain.

After scanning, commit extends the same packed snapshot with the remaining vertex/argument intervals, deduplicating already captured indices and preserving their contents even if packed storage grows. This guarantees the GPU consumes the very index bytes used to prove the vertex bounds. Snapshot byte counts describe the unique captured bytes; growing packed storage can additionally relocate the frozen prefix when pooled capacity is insufficient. The synchronous path refreshes directly from caller bytes except for these frozen index intervals. `setVertexBytes` and `setFragmentBytes` already own separate allocations copied at encoding and never become wrapped shadows.

Every unknown proof, whole/dynamic window, device-address form, writable buffer, function-table form, malformed/out-of-bounds window, or unavailable/older adapter keeps the whole allocation. Pipelines needing pointer/handle translation or reaching indirect command buffers provide no smaller proof. `useResource`, blits and buffer-backed textures also mark the underlying shadow allocation whole, even if a previous draw had a bounded use. This fallback is sticky for the command buffer. Unsupported indirect/argument-buffer selectors continue to reject submission; their support is not expanded here. Newly supported accesses must either supply a proven range or use the default whole-resource retention path.

## Packed storage and submission

Commit packs the merged intervals into one command-owned snapshot, preserving each destination offset separately. A queue-local, mutex-protected pool holds two reusable byte allocations, matching the usual two-flight queue. It retains capacity across frames and allocates uninitialized storage only when no idle allocation is large enough; it does not zero a whole vector before overwriting it. Small interval/segment metadata can still allocate. Each pending commit owns its allocation exclusively. Another commit cannot reuse it until application of the snapshot has finished.

The existing backend prepare callback still drains prior uses before refreshing the shared mapped GPU buffer. Refresh copies only the recorded intervals to their original offsets, then immediately returns the CPU snapshot allocation to the pool. GPU commands reference the mapped buffer, never the pooled snapshot. Failure/retirement and command destruction also return any outstanding storage. Resource owners remain retained through retirement. The synchronous commit path applies the same intervals directly before returning, using only the small index snapshot when indexed bounds are available.

Bytes outside the union may retain old GPU-allocation contents. The access proof guarantees that they cannot influence this command's result. Writing those CPU bytes after commit therefore cannot change its output; writing inside the union also cannot change it because those bytes have already been captured. A later command using a different ring window captures that window's then-current contents.

Existing timing/trace fields, including `snapshot`, `shadow_copy`, and `commit_call`, remain. Frame traces add `snapshot_bytes/frame` and `shadow_copy_bytes/frame`, averaged over the same reporting window and reset with it. Counts describe actual snapshot and GPU-allocation refresh bytes, including full fallbacks and deduplicating aliases. Synchronous commits report only the intermediate frozen index bytes (zero for nonindexed or unscannable draws) and the direct refresh bytes. Initial buffer construction and unrelated texture upload copies are excluded. `shadow_scanned_indices/frame` counts actual scanned elements, excluding cache hits. `shadow_full_reasons=indexed:N,whole_window:N,use_resource:N,blit:N,bounds:N,other:N` reports per-frame averages of distinct shadow allocations encountering each reason per command buffer. Repeated uses of the same reason count once; one allocation can have multiple reasons. Reasons and scan counts aggregate and reset with the existing reporting window; all existing field names remain unchanged.

Test render targets explicitly request private storage for macOS compatibility. It is registered for native execution and compile-only checks on macOS; it cannot compile or run on Linux without Foundation/Metal.

`tools/test-fuxi-metal-shadows.py` runs the host controls and optionally accepts an existing local ICD and glslang executable for production-backend pixel tests. It authors its own GLSL uniform-buffer fixture. Nonindexed and indexed u16/u32 draws use real vertex fetches and frozen indices. Full and ranged snapshots produce byte-identical lavapipe pixels after CPU vertex, uniform and index memory is overwritten following capture, with independently expected BGRA bytes. Controls cover synchronous/overlap submission and an old adapter without the optional proof extension. `--translator` additionally checks the real adapter against the hand-authored AIR control, verifying bounded vertex/fragment uniforms and the vertex descriptor union, including a full fallback when a shader argument shares that slot. The optional Vulkan test is registered alongside the existing render-merge test in `tools/ci/build.sh`; no barrier, merge or DrawPlanCache policy is changed.

The indexed CA-like host ring contains 130 draws per frame in one 4 MiB allocation. Each quad fetches four vertices at stride 32 (two float4 attributes), 64 fragment bytes, and six u16 indices: 204 bytes per draw. Draw slots occupy 256 bytes, so gaps outside the proven union remain untouched. The scan count is 780 indices/frame. This is an authored host workload, not a measured device allocation distribution.

## Linear texture extent lane

The supplied backboardd medians are 15,953,444 bytes/frame for each of commit snapshot and backend CPU shadow refresh, with about 24.98 distinct allocations/command encountering `other`. The roughly 880 creation messages describe a second, independent shadow: `Backend::linearTexture` first tries a Vulkan linear image alias of the buffer allocation. It queries format/external-import support, image memory requirements and subresource layout, then checks binding alignment, memory type, allocation extent, zero image-layout offset and exact row pitch. A mismatch (including Vulkan 640 versus Metal 768) falls back to an optimal image **only for usage ShaderRead (1)**. The texture retains the buffer, offset and Metal row stride. RenderTarget (4) and ShaderRead|RenderTarget (5) mismatch requests fail creation; A8 render targets are refused too.

`FuxiBuffer::_shadow` instead means the caller's no-copy CPU pages could not be imported. Its exposed `contents` remains those pages; the backend owns a separate mapped Vulkan buffer. Previously retaining any buffer texture marked that entire wrapped allocation full with reason `other`. Overlap commit captured all those pages, and the worker memcpy refreshed the entire mapped buffer after draining prior uses. Then, when sampling the image shadow, the backend recorded `CmdCopyBufferToImage` using `backingOffset`, `backingRow / texelBytes`, width and height. That last copy repitches **on the GPU**, not via a CPU row loop. It currently happens once per render run, so separate passes can repeat it. This lane leaves that policy intact.

There is no reverse optimal-image-to-buffer repitch for these shadows. Backend submission refuses GPU writes to the read-only image shadow. A renderable buffer texture must have successfully aliased the Vulkan buffer memory, and GPU writes become visible through that mapped allocation after submission retirement and cache invalidation. Ordinary mapped buffers and successfully imported shared pages therefore need no reverse memcpy. The earlier wrapped-buffer limitation still applies: GPU writes to an import-fallback buffer do not propagate to the original caller pages. This lane neither widens render-target admission nor claims to repair that existing limitation.

Consequently every logged **pitch-mismatch image shadow is sample-only**. The old `other:24.98` counter alone cannot establish how many allocations also had exact-alias render-target uses: it counted wrapped-buffer allocations, not image types or draw roles. No per-device sampled/target count can be recovered from the supplied aggregates. The new role counters distinguish those cases on a subsequent trace without device access here.

Metal's shared buffer/texture storage must expose the same logical texels through CPU buffer writes, `replaceRegion`, views and texture reads. CPU writes before commit must reach subsequent GPU samples, and overlap snapshots must remain immutable after commit returns. Raw `contents` pointers and caller-owned no-copy pages can change without a method call, so neither creation-time contents nor observed `replaceRegion` calls prove an unchanged source. Every commit still refreshes the required bytes. The ShaderRead-only buffer-texture CPU transfer path now accesses the wrapped pages when `_shadow` is set, fixing `replaceRegion` writes that previously went into the internal buffer and were overwritten by the next commit; `getBytes` for those textures sees the same logical pages. Other texture usages retain their existing CPU transfer path.

### Chosen bound and alternatives

Option **(b)** bounds only known ShaderRead 2D, single-level buffer textures, including identity views, to `[bufferOffset, bufferOffset + (height - 1) * bytesPerRow + width * texelBytes)`. The full logical texture is included regardless of shader coordinates. This deliberately includes inter-row padding, using one interval instead of a per-row list; the final row needs only its texels. Checked multiplication, stride, texel alignment, offset and allocation bounds precede insertion. Invalid metadata forces the bounds full fallback. Views, multiple textures, vertex/index/argument uses and aliases union into the existing per-allocation tracker. Full fallbacks remain sticky. Texture bindings without draws add no sample requirement.

Targets, unclassified texture uses, explicit `useResource`, blits, unknown/writable shader accesses and unsupported texture shapes/usages keep today's full path. Both synchronous direct refresh and overlap snapshot/apply consume the same ranges. Buffer ownership, prepare/drain ordering, barrier/merge policy and DrawPlanCache are unchanged.

Option **(a)** was not selected: explicit DRM-modifier image creation would add device-extension negotiation, per-format/modifier/external-memory compatibility queries and new binding/layout validation. No supplied device observation proves that combination is supported for these buffers or that the pitches meet its requirements. The existing GPU buffer-to-image transfer already handles arbitrary validated Metal pitches; this lane bounds the preceding CPU copies without changing image admission. No support is assumed and no new extension is enabled. Texel-buffer/shader alternatives would also change translation/descriptor behavior.

Option **(c)** cannot remove the logged pitch-mismatch shadows' refreshes because they cannot be render targets. Exact-alias targets can also share wrapped allocations with CPU-visible or other GPU uses. This lane keeps their full path instead of adding a new load-action/ownership/readback protocol. It does not skip refresh based on speculative CPU or GPU ownership.

All existing trace fields and `shadow_full_reasons` names remain. The sibling `texture_shadow_uses=sampled:N,target:N,other:N` counts distinct wrapped shadow allocations per command for each observed texture role (roles may overlap). `texture_shadow_bytes/frame` is the actual CPU refresh range size of those allocations, including any full fallback or union with other buffer uses, deduplicated per allocation. In overlap mode the same bytes enter the snapshot. `texture_repitched_bytes/frame` separately counts logical texel bytes in recorded GPU buffer-to-image image-shadow refreshes, including repeated render runs and buffers that did not need a CPU shadow. It is not CPU memcpy traffic. These fields aggregate/reset with the existing frame window.

### Host evidence and limits

The existing shadow runner now also builds an authored R8/RG8 sampling adapter and production-backend texture pixel fixture. It uses 25 pitch-mismatched textures, cycling the supplied 621x358/row768 A8, 230x186/row480 RG8, 138x138/row256 A8 and 635x147/row768 A8 shapes, all at offset 256. Five draws per texture make 125 draws in one submission, followed by independently checked readback regions. Sample coordinates span each source through its final texel, including the tight last row. Wrapped CPU allocation lengths are **synthetic**: 638,137 bytes each, with 19 extra bytes in the last, intentionally totaling the observed 15,953,444 bytes. Their distribution and extent-to-allocation ratio are not device measurements.

| --- | ---: | ---: |
| Commit snapshot | 15,953,444 bytes | 3,346,977 bytes |
| Backend shadow refresh | 15,953,444 bytes | 3,346,977 bytes |
| Both stages | 31,906,888 bytes | 6,693,954 bytes |

That is a 79.02% CPU byte reduction for this fixture. The unchanged GPU repitch count is 13,719,600 logical bytes/frame across its 125 separate render runs. The actual device reduction depends on wrapped lengths, texture extents, aliases and full fallback uses; a tightly sized buffer may save only its prefix/suffix. No backboardd timing improvement or 120 Hz qualification is claimed.

Lavapipe pixels match independently expected bytes and full-copy reference pixels for three changing CPU frames, including writes after capture, bounded copies and an explicit-resource full fallback, in synchronous and overlap/submit-reuse modes. The target itself is an exact-alias renderable linear texture: shader output is checked both through readback and directly through the CPU mapped backing buffer after retirement. Additional Clear/Load preservation controls check alias CPU visibility. Existing M9o controls cover mismatch diagnostics, read-only shadow write refusal, tight final rows, CPU/GPU buffer changes, budget rollback and poisoned ownership.
